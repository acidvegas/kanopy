REST API

kanopy 1.2.4. Every endpoint the web app uses. This page is built from openapi.json (OpenAPI 3.1), which every kanopy also serves at /openapi.json.

Overview#

The REST API the kanopy web app uses. Agents should prefer the MCP endpoint (/mcp), which answers in compact text.

Auth. Send an API token in the X-Key header (create one under Settings), or use the kb_session cookie from /api/login. A sent X-Key is the only credential checked. Tokens can use the board only: routes marked cookie-only (account, teams, tokens, users, sharing, settings) refuse them with 403. Read-only (viewer) tokens can only read, and a token limited to some projects sees only those.

Writes with the cookie must be same-origin and send JSON (or multipart for uploads); token requests skip that check.

Errors come back as {"error": "..."} with 400, 401, 403, 404, 409 or 415.

Revision. Every /api response carries X-Revision, the board's change counter; a successful write bumps it and also sends X-Revision-Was.

POST /api/setup#

Create the first admin on an empty board and sign in.

Works only while the board has no users. Sets the session cookie. If KANOPY_KEY is set, it is imported as this admin's API token.

No sign-in needed.

Body application/json

FieldTypeDescription
username requiredstring
password requiredstringAt least 8 characters for new accounts
  • 200 OK: Ok
  • Errors: 400, 403

POST /api/login#

Sign in.

Sets the kb_session cookie (30 days). Five failed sign-ins from one address within 15 minutes lock it out for the rest of that window. When the account has a second factor, no cookie is set yet: the response is {"two_factor": [...], "ticket": "..."} and sign-in finishes at /api/login/2fa within 5 minutes.

No sign-in needed.

Body application/json

FieldTypeDescription
username requiredstring
password requiredstringAt least 8 characters for new accounts
  • 200 OK: any
  • Errors: 400, 403

POST /api/login/2fa#

Finish signing in with a second factor.

Send code (authenticator code or a recovery code) or passkey (the browser's assertion as JSON, from /api/login/passkey). Sets the session cookie. Five wrong tries end the ticket; wrong tries also count toward the address's sign-in limit.

No sign-in needed.

Body application/json

FieldTypeDescription
ticket requiredstring
codestring
passkeyobject
  • 200 OK: Ok
  • Errors: 400, 403

POST /mcp#

MCP endpoint (streamable HTTP, stateless, JSON responses).

Takes API tokens only. Without one, only the handshake and the tool list answer. Send X-Agent to name the agent in comments and history, and send back the Mcp-Session-Id header you were given so the session can claim tasks as itself. The tools are listed in the README.

API token only.

Body application/json: One JSON-RPC 2.0 request object; batches are not supported

  • 200 One JSON-RPC response, or 202 with no body for a notification
  • 202 Accepted (a JSON-RPC notification)
  • Errors: 400
